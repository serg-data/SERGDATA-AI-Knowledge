# SERGDATA AI-Knowledge

Локальная база знаний для ИИ-агентов и языковых моделей. Проект индексирует исходный код, техническую документацию и локальные текстовые документы, выполняет полнотекстовый поиск и предоставляет инструменты поиска и чтения через MCP.

> **Статус:** личный проект, подготовленный к публикации. Перед использованием проверьте зависимости и настройки под свою среду. Индекс и исходные материалы намеренно не входят в репозиторий.

## Зачем нужен проект

Обычная языковая модель не знает содержимое ваших локальных репозиториев и документов. SERGDATA AI-Knowledge создаёт локальный поисковый индекс, чтобы совместимый ИИ-клиент мог находить релевантные фрагменты, открывать исходные файлы и использовать подтверждённые источники при анализе и разработке.

## Возможности

- Индексирование поддерживаемых текстовых файлов и документов.
- Полнотекстовый поиск на SQLite FTS5.
- Разбиение содержимого на фрагменты с сохранением диапазонов строк.
- Извлечение текста из PDF, DOCX, ODT, EPUB и IPYNB, а также исходников и конфигураций поддерживаемых расширений.
- MCP-инструменты для поиска по базе и чтения исходных файлов.
- Отдельный скрипт синхронизации заметок о релизах GitHub для локальных репозиториев.

### Ограничения

- OCR отключён: PDF, состоящие только из сканов без текстового слоя, автоматически не распознаются.
- Индексатор ограничивает размер одного индексируемого файла значением 5 МиБ. Это лимит текущей версии, а не гарантия поддержки любых больших файлов.
- Содержимое выдачи при чтении ограничено настройкой в `server.py`; для больших материалов нужно запрашивать нужные диапазоны частями.
- Качество извлечения зависит от структуры исходного документа и качества его текстового слоя.

## Структура

```text
SERGDATA-AI-Knowledge/
├── kb.py                       # Индексирование и поиск
├── server.py                   # MCP-сервер поиска и чтения
├── document_readers.py         # Извлечение текста из файлов
├── release_sync.py             # Синхронизация release notes
├── repositories.json           # Список публичных Git-репозиториев
├── requirements-knowledge.txt  # Python-зависимости
├── documents/                  # Локальные документы (не публикуются)
├── code/                       # Клонированные репозитории (не публикуются)
└── index/                      # SQLite-индекс и состояние (не публикуются)
```

Папки `documents`, `code` и `index` создаются/заполняются локально. Их содержимое не должно попадать в публичный Git-репозиторий.

## Требования

- Python 3.10 или новее (проект разрабатывался и проверялся на Python 3.12).
- SQLite с поддержкой FTS5 (обычно включена в сборки SQLite, поставляемые с Python).
- Пакеты из `requirements-knowledge.txt`.

## Установка на Windows (PowerShell)

```powershell
git clone https://github.com/ВАШ-АККАУНТ/SERGDATA-AI-Knowledge.git
cd SERGDATA-AI-Knowledge
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-knowledge.txt
New-Item -ItemType Directory -Force documents, code, index
```

Замените `ВАШ-АККАУНТ` на имя своего GitHub-аккаунта. Репозиторий не содержит ваши документы и кодовые базы: добавьте нужные локальные материалы в `documents/` и клонируйте необходимые публичные репозитории в `code/`. Не копируйте в эти каталоги конфиденциальные данные, если они могут случайно попасть в систему резервного копирования или индекс.

## Первичная индексация

Из корня проекта выполните:

```powershell
python .\kb.py --help
```

Если в вашей версии скрипта нет справки `--help`, изучите точку входа в `kb.py` и используйте поддерживаемый ею режим запуска. Не запускайте переиндексацию рабочей базы без резервной копии.

## Подключение MCP

`server.py` предоставляет MCP-сервер. Настройте ваш MCP-клиент так, чтобы он запускал `server.py` из каталога проекта с выбранным виртуальным окружением Python. Конкретный формат конфигурации зависит от клиента. Не публикуйте конфигурации, содержащие локальные пути, токены или другие секреты.

## Безопасность и приватность

- База `index/knowledge.db`, состояние синхронизации и локальные исходники исключены из Git.
- Не добавляйте токены, пароли, приватные ключи, файлы `.env`, личные документы и закрытые репозитории.
- Перед каждым публичным коммитом проверяйте `git status` и `git diff --cached`.
- При случайной публикации секрета удаление файла из последующего коммита не отменяет утечку: секрет нужно отозвать или заменить.

## Лицензия

## Вклад и сообщения об ошибках

Перед отправкой изменений проверьте синтаксис:

```powershell
python -m py_compile .\kb.py .\server.py .\document_readers.py .\release_sync.py
```

Синтаксическая проверка не заменяет функциональные тесты и проверку на тестовой копии базы.
